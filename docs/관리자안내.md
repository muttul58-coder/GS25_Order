# 관리자 안내 — 명절마다 주문서 갱신하기

설날·추석마다 상품, 바코드, 행사, 날짜가 전부 바뀝니다.
**개발자 없이 이 문서만 보고 갱신할 수 있습니다.**

고치는 파일은 `season.json` **하나**이고, 실행은 GitHub 화면에서 **버튼 한 번**입니다.

---

## 준비물

- GitHub 계정 (이 저장소에 쓰기 권한)
- 새 시즌 **바코드북 PDF**
- 새 시즌 **카탈로그 주소**

---

## 1단계 — 바코드 PDF 올리기

1. 저장소에서 `BarcodeSource` 폴더를 엽니다
2. 오른쪽 위 **Add file → Upload files**
3. 새 PDF를 끌어다 놓고 아래 **Commit changes** 클릭

> 파일 이름은 아무거나 괜찮습니다. 다음 단계에서 그 이름을 적어주면 됩니다.
> 예전 PDF는 지우지 않아도 됩니다.

---

## 2단계 — 카탈로그 주소 찾기

1. 새 시즌 카탈로그 사이트를 엽니다 (예: `https://gs25mobile.com/2026_2nd/category`)
2. 주소창에서 `/category` 앞부분까지가 **카탈로그 폴더**입니다
   → `https://gs25mobile.com/2026_2nd`
3. 여기에 `/products.json` 을 붙인 것이 카탈로그 주소입니다
   → `https://gs25mobile.com/2026_2nd/products.json`
4. 그 주소를 브라우저에 붙여넣어 **글자가 잔뜩 나오면 정상**입니다

---

## 3단계 — 행사 기간 확인

카탈로그 사이트에서 **사전행사(사전예약) 안내 배너**를 찾으면 이렇게 적혀 있습니다.

> 사전 구매 증정 행사 **2026.08.17(월) ~ 2026.09.04(금)**, 19일간
> 삼성/KB국민/비씨/신한카드 결제 시

여기서 세 가지를 적어둡니다.

| 적을 값 | 위 예시에서 | 설명 |
|---|---|---|
| 사전행사시작 | `2026-08-17` | 이 날부터 사전행사 행사가 자동 선택됩니다 |
| 본행사시작 | `2026-09-05` | **사전행사 끝난 다음 날**. 이 날부터 본행사 행사로 바뀝니다 |
| 사전행사조건 | `삼성/KB국민/비씨/신한카드 결제 시` | 사전행사 안내에 함께 표시됩니다 |

> 사전행사 시작 **전**에는 어떤 행사도 자동 선택되지 않습니다 (아직 행사 기간이 아니므로).
> 조건이 따로 없으면 `사전행사조건` 은 `""` 로 비워두세요.

---

## 4단계 — `season.json` 고치기

저장소 첫 화면에서 `season.json` 을 클릭하고 **연필 아이콘(Edit)** 을 누릅니다.

```json
{
  "매장": {
    "이름": "LG 생산기술원점",
    "담당자": "양창호",
    "전화번호": "010-7568-3522"
  },
  "시즌": {
    "이름": "2027 설날",
    "카탈로그주소": "https://gs25mobile.com/2027_1st/products.json",
    "바코드PDF": "BarcodeSource/20270105.pdf"
  },
  "행사기간": {
    "사전행사시작": "2027-01-05",
    "본행사시작": "2027-01-20",
    "사전행사조건": "삼성/KB국민/비씨/신한카드 결제 시"
  }
}
```

바꿀 곳은 **`시즌`과 `행사기간`** 뿐입니다. `바코드PDF` 는 1단계에서 올린 파일 이름을
`BarcodeSource/` 뒤에 그대로 적습니다.

다 고치면 아래 **Commit changes** 를 누릅니다.

> ⚠️ 쉼표(`,`)와 큰따옴표(`"`)를 지우지 마세요. 형식이 깨지면 실행이 멈추고
> 무엇이 잘못됐는지 알려줍니다. 그때 다시 고치면 됩니다.

매장 이름·담당자·전화번호가 바뀌었다면 `매장` 부분도 같이 고치세요.
주문서 맨 위에 그대로 표시됩니다.

---

## 5단계 — 실행

1. 저장소 위쪽 **Actions** 탭
2. 왼쪽 목록에서 **시즌 갱신**
3. 오른쪽 **Run workflow** 버튼
4. 옵션 확인 후 초록색 **Run workflow**

| 옵션 | 설명 |
|---|---|
| 바코드도 다시만들기 | 새 PDF를 올렸으면 **체크** (3~5분 걸립니다). 날짜·매장정보만 고쳤으면 체크 해제 |
| 확인만하기 | 실제로 바꾸지 않고 결과만 봅니다. 처음이라 불안하면 이걸로 한 번 돌려보세요 |

노란 점이 **초록 체크(✓)** 로 바뀌면 끝입니다.
**1~2분 뒤** 주문서에 반영됩니다.

https://muttul58-coder.github.io/GS25_Order/order_form.html

> 화면이 그대로면 **Ctrl+F5** 로 강제 새로고침하세요.

---

## 6단계 — 확인 (중요)

갱신 후 **반드시** 확인해 주세요.

1. 상품코드 몇 개를 넣어 **상품 이름과 가격**이 맞는지
2. **행사**가 카탈로그와 같은지
3. **인쇄해서 바코드를 실제 스캐너로 찍어보기**

> 바코드가 제일 중요합니다. 명절마다 **같은 상품코드가 다른 상품을 가리키기** 때문에
> (2026 추석에는 유지된 코드 371개의 내용물이 바뀌었습니다) 여기가 틀어지면
> 주문서에 찍힌 바코드가 엉뚱한 상품으로 스캔됩니다.

---

## 실행이 빨간 ✗ 로 끝났을 때

빨간 ✗ 를 누르고 **시즌 갱신 실행** 항목을 펼치면 `[!]` 로 시작하는 줄에 원인이 있습니다.

| 메시지 | 뜻과 조치 |
|---|---|
| `바코드 PDF가 없습니다` | `season.json` 의 `바코드PDF` 이름과 실제 올린 파일 이름이 다릅니다 |
| `카탈로그를 읽지 못했습니다` | `카탈로그주소`가 틀렸습니다. 브라우저에 붙여넣어 열리는지 확인 |
| `season.json 형식이 잘못됐습니다` | 쉼표나 따옴표가 빠졌습니다 |
| `처음 보는 혜택 아이콘` | 아래 참고 |
| `두 소스가 완전히 일치하지 않습니다` | PDF와 카탈로그의 상품이 다릅니다. 같은 시즌 파일이 맞는지 확인 |

### "처음 보는 혜택 아이콘" 이 나오면

행사 표시(1+1, 2+1 …)는 카탈로그에 **숫자가 아니라 그림**으로만 들어 있어서,
새 그림이 나오면 사람이 한 번 봐줘야 합니다. **이것만 수동 작업입니다.**

1. 실행 화면 아래 **Artifacts** 에서 `확인이-필요한-아이콘` 을 내려받습니다
   (그림 한 장에 번호와 함께 모아 놓았습니다)
2. 그림을 보고 `season.json` 의 `구매혜택` 에 옮겨 적습니다

```json
"구매혜택": {
  "행사": {
    "12": "2+1",     ← 그림에 "2+1" 이라고 적혀 있으면
    "56": "3+1"      ← 새 번호를 이렇게 추가
  },
  "행사아님": [1, 3, 4, 57]   ← 무료배송·냉장·할인 등은 번호만 추가
}
```

3. 저장하고 5단계를 다시 실행합니다

> 그림에 `9월 5일부터` 같은 날짜가 함께 적힌 것도 있습니다. 비율만 보고 적으면 됩니다
> (`3+1 9월 5일부터` → `"3+1"`). 날짜는 `행사기간` 에서 따로 관리합니다.

## 자주 묻는 것

**Q. 잘못 눌렀는데 되돌릴 수 있나요?**
네. 모든 갱신이 커밋으로 남습니다. 개발자에게 "이전 상태로 되돌려달라"고 하면 됩니다.
불안하면 **확인만하기** 옵션으로 먼저 돌려보세요.

**Q. 매장 전화번호만 바꾸고 싶어요.**
`season.json` 의 `매장` 부분만 고치고, **바코드도 다시만들기 체크를 해제**하고 실행하세요. 몇 초면 끝납니다.

**Q. 행사가 카탈로그와 다르게 나옵니다.**
주문서의 행사 칸은 언제든 직접 바꿀 수 있습니다. 매장 사정으로 다른 경우가 있어
자동 선택은 어디까지나 처음 채워주는 값입니다.

**Q. 상품이 몇 개인지 어떻게 아나요?**
실행 기록의 `시즌 갱신 실행` 항목에 상품 수, 행사 수가 모두 찍힙니다.
카탈로그 사이트의 "사전 구매 행사 총 ○○품목" 과 비교해 보면 맞게 읽었는지 확인됩니다.
