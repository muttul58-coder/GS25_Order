# 준비 — 두 가지를 종이에 적어두세요

실제로 고칠 값은 6개뿐입니다. 그중 4개를 여기서 미리 알아냅니다.

## 준비 A — 카탈로그 주소 찾기

1. 새 시즌 GS25 카탈로그 사이트를 엽니다
   예: `https://gs25mobile.com/2026_2nd/category`
2. 주소창에서 **`/category` 앞부분까지**가 카탈로그 폴더입니다
   → `https://gs25mobile.com/2026_2nd`
3. 거기에 **`/products.json`** 을 붙입니다
   → `https://gs25mobile.com/2026_2nd/products.json`

**✅ 확인 방법** — 그 주소를 브라우저 주소창에 붙여넣고 엽니다.
**글자가 빽빽하게 잔뜩 나오면 정상**입니다. 무슨 뜻인지 읽으실 필요는 없습니다.
"404" 나 빈 화면이 나오면 주소가 틀린 것입니다.

> 시즌 폴더 이름은 매번 바뀝니다. `2026_2nd`(추석) 다음은 보통 `2027_1st`(설날) 입니다.

## 준비 B — 행사 기간 3가지 적기

카탈로그 사이트에서 **사전행사(사전예약) 안내 배너**를 찾습니다. 이렇게 적혀 있습니다.

> 사전 구매 증정 행사 **2026.08.17(월) ~ 2026.09.04(금)**, 19일간
> 삼성/KB국민/비씨/신한카드 결제 시

여기서 세 가지를 뽑아 적습니다.

| 적을 값 | 위 예시라면 | 어디서 나오나 |
|---|---|---|
| **사전행사 시작** | `2026-08-17` | 배너의 **시작일** 그대로 |
| **본행사 시작** | `2026-09-05` | 배너의 **끝난 날 + 1일** ← 주의 |
| **사전행사 조건** | `삼성/KB국민/비씨/신한카드 결제 시` | 배너의 조건 문구 그대로 |

> ⚠️ **본행사 시작은 배너에 안 적혀 있습니다.** 사전행사가 끝난 **다음 날**입니다.
> 위 예시는 사전행사가 9월 4일에 끝나므로 본행사는 **9월 5일**입니다.

> 조건 문구가 따로 없으면 `사전행사 조건:` 뒤를 비워두시면 됩니다.
> 사전행사 시작 **전**에는 어떤 행사도 자동 선택되지 않습니다 (아직 행사 기간이 아니므로).

**✅ 확인 방법** — 배너에 "총 ○○품목" 같은 숫자가 있으면 함께 적어두세요.
3단계 실행 결과에 나오는 사전행사 품목 수와 같아야 합니다. 공짜 검산입니다.

> 파일 이름은 아무거나 괜찮습니다 (한글도 됩니다). 2단계에서 그 이름을 그대로 적어주면 됩니다.
> **예전 PDF는 지우지 마세요.** 문제가 생겼을 때 되돌릴 근거가 됩니다.

> 직접 찾아가려면: 저장소 → `BarcodeSource` 폴더 → **Add file** → **Upload files**

# 2단계 — `시즌설정.txt` 고치기

**즐겨찾기 2번**을 엽니다. 편집 화면이 바로 열립니다.

**쌍점(`:`) 뒤의 값만 고치시면 됩니다.**

```
매장 이름: LG 생산기술원점
매장 담당자: 양창호
매장 전화번호: 010-7568-3522

시즌 이름: 2027 설날                                    ← 고침
카탈로그 주소: https://gs25mobile.com/2027_1st/products.json   ← 고침 (준비 A)
바코드 PDF: BarcodeSource/20270105.pdf                  ← 고침 (1단계 파일 이름)

사전행사 시작: 2027-01-05                               ← 고침 (준비 B)
본행사 시작: 2027-01-20                                 ← 고침 (준비 B)
사전행사 조건: 삼성/KB국민/비씨/신한카드 결제 시          ← 고침 (준비 B)
```

**보통 고치는 건 아래 6줄뿐입니다.** 위의 매장 3줄은 담당자나 전화번호가
바뀌었을 때만 고치시면 됩니다 (주문서 맨 위에 그대로 표시됩니다).

다 고치면 아래 **Commit changes** 를 누릅니다.

## 너무 조심하지 않으셔도 됩니다

이렇게 적어도 알아서 읽습니다.

| 이렇게 적어도 | 이렇게 읽습니다 |
|---|---|
| `사전행사 시작: 2027.1.5` 또는 `2027/01/05` | `2027-01-05` |
| `시즌 이름: "2027 설날",` (따옴표·끝쉼표) | `2027 설날` |
| `담당자: 양창호` (짧은 이름) | `매장 담당자` |
| `카탈로그 링크:` / `바코드파일:` | `카탈로그 주소` / `바코드 PDF` |

- `#` 으로 시작하는 줄은 설명이라 무시됩니다. 지우셔도 되고 두셔도 됩니다.
- 줄 순서는 상관없고, 빈 줄도 마음대로 넣으셔도 됩니다.

## 대신 이름을 잘못 적으면 멈춥니다

`사전행사시자` 처럼 오타를 내면 조용히 넘어가지 않고 이렇게 알려줍니다.

```
  6번째 줄:  사전행사시자: 2027-01-05
      -> 모르는 이름입니다.  '사전행사시작' 을(를) 쓰시려던 것 같습니다.
```

그냥 넘어가면 "사전행사 날짜가 없는" 상태로 배포되기 때문에 일부러 멈춥니다.
틀린 곳이 여러 군데여도 **한 번에 모두** 알려주니, 한 줄씩 고쳐가며 여러 번
실행하실 필요가 없습니다.

**✅ 이렇게 되면 성공** — 파일 화면에 고친 값이 그대로 보입니다.

# 3단계 — 갱신 실행

**즐겨찾기 3번**을 엽니다.

1. 오른쪽 **`Run workflow ▾`** 버튼 클릭
2. `Use workflow from` 은 **`Branch: main`** 그대로 둡니다
3. 옵션 두 개를 확인합니다 (아래 표)
4. 초록색 **`Run workflow`** 클릭

| 옵션 | 언제 체크하나 |
|---|---|
| **바코드도 다시만들기** | 새 PDF를 올렸으면 **반드시 체크** (601장 그리느라 3~5분) |
| | 날짜·전화번호만 고쳤으면 **체크 해제** (몇 초면 끝남) |
| **확인만하기** | 실제로 바꾸지 않고 결과만 봅니다. **연습용** |

노란 점(●)이 돌다가 **초록 체크(✓)** 로 바뀌면 끝입니다.

**✅ 이렇게 되면 성공** — 초록 체크가 뜨고, 실행 기록을 열면 이런 줄이 보입니다.

```
   상품 601개, 시세반영 10개
   행사: 사전행사 127개 (2027-01-05 ~) / 본행사 290개 (2027-01-20 ~)
   [OK] 상품 601개 ↔ 바코드 601개 완전 일치
```

> **사전행사 품목 수**를 준비 B에서 적어둔 배너의 "총 ○○품목" 과 비교해 보세요.
> 같으면 제대로 읽은 것입니다.

**1~2분 뒤** 주문서에 반영됩니다. 즐겨찾기 4번으로 확인하세요.
화면이 그대로면 **Ctrl+F5** 로 강제 새로고침하세요.

> `Run workflow` 버튼이 안 보이면 로그인이 안 된 상태입니다.
> 직접 찾아가려면: 저장소 위쪽 **Actions** 탭 → 왼쪽 목록의 **시즌 갱신**

# 4단계 — 확인 ★ 생략하지 마세요

갱신이 초록 체크로 끝나도 **반드시** 확인해 주세요.

### 확인 1. 상품 이름과 가격

주문서에서 상품코드 **5개쯤** 넣어보고 카탈로그와 대조합니다.
첫 코드, 중간 코드, 마지막 코드를 섞어서 골라주세요.

### 확인 2. 행사

카탈로그에 적힌 행사와 같은지 봅니다.
**지금이 사전행사 기간이면 본행사 상품은 행사가 안 붙는 게 정상입니다.**
(아래 "행사 미리보기" 참고)

### 확인 3. 바코드 스캔 ★ 제일 중요

**인쇄해서 실제 스캐너로 찍어보세요.**

> 명절마다 **같은 상품코드가 다른 상품을 가리킵니다.**
> 2026 추석에는 그대로 남은 코드 371개의 **내용물이 바뀌었습니다.**
> 여기가 틀어지면 주문서에 찍힌 바코드가 **엉뚱한 상품으로 스캔됩니다.**
> 화면상으로는 아무 문제가 없어 보이기 때문에, 스캔해보지 않으면 모릅니다.

# 행사 미리보기 (본행사 화면 미리 보기)

상품마다 **사전행사와 본행사 행사가 다릅니다.** 2026 추석 기준으로 601개 중
**289개가 서로 다르고, 167개는 본행사에야 행사가 켜집니다.**

> 예: `08-05` 농협안심 한우 1호 → 사전행사 **없음**, 본행사 **5+1**
> 지금 행사가 안 붙는다고 잘못된 게 아니라, 본행사 시작일부터 붙습니다.

본행사가 시작되기 전에 "그날 화면이 어떻게 보이는지" 미리 볼 수 있습니다.
**즐겨찾기 5번** (`?admin=1`) 으로 열면 오른쪽 아래에 관리자 메뉴가 나옵니다.

| 버튼 | 보이는 화면 |
|---|---|
| 행사 시작 전 | 아직 어떤 행사도 안 붙는 상태 |
| 사전행사 | 사전행사 기간 |
| **본행사** | 본행사 시작일 이후 |
| 직접 고르기 | 원하는 날짜 아무거나 |
| **테스트 끝내기** | 실제 날짜로 돌아감 |

메뉴 없이 바로 열려면 주소 뒤에 `?test=main`(본행사) / `?test=pre`(사전행사) 를
붙이셔도 됩니다.

### 테스트 모드 끄기

> ⚠️ 테스트 중에는 화면 맨 위에 **빨간 띠**가 뜨고 **인쇄물에도 찍힙니다.**
> 테스트로 뽑은 주문서가 진짜와 구분되지 않으면 안 되기 때문입니다.
> **빨간 띠가 보이는 주문서는 실제 주문에 쓰지 마세요.**

끄는 방법 세 가지 — 빨간 띠의 **테스트 끄기** 버튼 / 관리자 메뉴의
**테스트 끝내기** / 그냥 **탭(창) 닫기**.

> 주소에서 `?admin=1` 만 지우는 것으로는 **꺼지지 않습니다.** 관리자 메뉴만
> 사라지고 테스트 모드는 그 탭에 남습니다. 그때는 빨간 띠의 **테스트 끄기** 를 누르세요.

바뀌는 것은 **행사 자동 선택에 쓰는 날짜뿐**입니다. 주문 일시와 배송 희망일은
실제 날짜 그대로입니다.

**판단 기준은 간단합니다 — 빨간 띠가 없으면 진짜 주문서입니다.**

# 실행이 빨간 ✗ 로 끝났을 때

당황하지 않으셔도 됩니다. **실패해도 주문서는 그대로입니다** — 갱신이
끝까지 성공했을 때만 반영되기 때문입니다.

빨간 ✗ 를 누르고 **시즌 갱신 실행** 항목을 펼치면 `[!]` 로 시작하는 줄에 원인이 있습니다.

| 메시지 | 뜻과 조치 |
|---|---|
| `시즌설정.txt 을(를) 읽지 못했습니다` | 몇 번째 줄이 왜 잘못됐는지 바로 아래에 적혀 있습니다. 그대로 고치세요 |
| `바코드 PDF가 없습니다` | `바코드 PDF` 줄의 이름과 실제 올린 파일 이름이 다릅니다. 대소문자·띄어쓰기까지 확인 |
| `카탈로그를 읽지 못했습니다` | `카탈로그 주소`가 틀렸습니다. 브라우저에 붙여넣어 열리는지 확인 (준비 A) |
| `확인이 필요한 아이콘` | 아래 참고. **정상적인 과정입니다** |
| `두 소스가 완전히 일치하지 않습니다` | PDF와 카탈로그의 상품이 다릅니다. **같은 시즌 파일이 맞는지** 확인 |

## "확인이 필요한 아이콘" 이 나오면

행사 표시(1+1, 2+1 …)는 카탈로그에 **숫자가 아니라 그림**으로만 들어 있습니다.
그래서 프로그램이 **아이콘 그림 자체를 기억해 두었다가** 새 시즌 그림과 맞춰봅니다.

- 그림이 지난 시즌과 **똑같으면** — 번호가 12번에서 37번으로 바뀌었어도
  알아서 같은 행사로 처리합니다. **하실 일이 없습니다.**
- 그림이 **처음 보는 것**이거나 **번호는 그대로인데 그림이 바뀌었으면** —
  이때만 멈추고 물어봅니다. **이 부분만 사람 손이 필요합니다.**

물어보면 이렇게 하세요.

1. 실행 화면 맨 아래 **Artifacts** 에서 `확인이-필요한-아이콘` 을 내려받습니다
   (번호가 붙은 그림 한 장에 모아 놓았습니다)
2. 그림을 보고, 실행 기록이 알려준 줄을 `시즌설정.txt` **맨 아래에** 붙여넣고 값만 고칩니다

```
구매혜택 56: 3+1      ← 그림에 "3+1" 이라고 적혀 있으면
구매혜택 57: 없음      ← 무료배송·냉장·할인 등 덤이 아닌 그림이면 '없음'
```

3. 저장하고 3단계를 다시 실행합니다

**한 번 적어두면 그 그림은 계속 기억되므로, 다음 시즌부터는 다시 묻지 않습니다.**

> 그림에 `9월 5일부터` 같은 날짜가 함께 적힌 것도 있습니다. **비율만** 보고 적으면 됩니다
> (`3+1 9월 5일부터` → `3+1`). 날짜는 `사전행사 시작` / `본행사 시작` 에서 따로 관리합니다.

> **"번호는 그대로인데 그림이 바뀌었습니다"** 가 제일 조심할 경우입니다.
> 그냥 넘어가면 **작년 비율로 올해 주문이 나갑니다.** 일부러 멈추게 해두었습니다.

# 자주 묻는 것

**Q. 잘못 눌렀는데 되돌릴 수 있나요?**
네. 모든 갱신이 기록으로 남습니다. 개발자에게 "이전 상태로 되돌려달라"고 하면 됩니다.
불안하시면 **확인만하기** 옵션으로 먼저 돌려보세요.

**Q. 매장 전화번호만 바꾸고 싶어요.**
`시즌설정.txt` 의 해당 줄만 고치고, **바코드도 다시만들기 체크를 해제**하고
실행하세요. 몇 초면 끝납니다.

**Q. `season.json` 은 뭔가요? 고쳐야 하나요?**
아니요. 구매혜택 **아이콘 그림을 기억해두는 파일**이라 프로그램이 알아서 씁니다.
갱신할 때마다 자동으로 바뀌므로 열어보거나 고치지 마세요.

**Q. 행사가 카탈로그와 다르게 나옵니다.**
주문서의 행사 칸은 **언제든 직접 바꿀 수 있습니다.** 매장 사정으로 다른 경우가 있어,
자동 선택은 어디까지나 처음 채워주는 값입니다.

**Q. 상품이 몇 개인지 어떻게 아나요?**
실행 기록의 **시즌 갱신 실행** 항목에 상품 수와 행사 수가 모두 찍힙니다.

**Q. 화면이 예전 그대로예요.**
브라우저가 옛 파일을 기억하고 있는 것입니다. **Ctrl+F5** 로 강제 새로고침하세요.

**Q. 수량과 지급수량이 왜 다른가요?**
**수량**은 손님이 돈 내는 개수, **지급수량**은 실제로 나가는 개수(덤 포함)입니다.
`2+1` 행사에서 10개를 사면 수량 10 / 지급수량 15 이고, **금액은 10개 값**입니다.
행사는 값을 깎는 게 아니라 덤을 더 주는 방식입니다.

□ 준비 B  사전행사 시작 / 본행사 시작(= 사전행사 끝난 다음 날) / 조건 문구 적기

□ 3단계   갱신 실행 (새 PDF면 '바코드도 다시만들기' 체크) → 초록 체크(✓)
