## 2단계 — 카탈로그 주소 찾기

1. 새 시즌 카탈로그 사이트를 엽니다 (예: `https://gs25mobile.com/2026_2nd/category`)
2. 주소창에서 `/category` 앞부분까지가 **카탈로그 폴더**입니다
   → `https://gs25mobile.com/2026_2nd`
3. 여기에 `/products.json` 을 붙인 것이 카탈로그 주소입니다
   → `https://gs25mobile.com/2026_2nd/products.json`
4. 그 주소를 브라우저에 붙여넣어 **글자가 잔뜩 나오면 정상**입니다

## 3단계 — 행사 기간 확인

카탈로그 사이트에서 **사전행사(사전예약) 안내 배너**를 찾으면 이렇게 적혀 있습니다.

> 사전 구매 증정 행사 **2026.08.17(월) ~ 2026.09.04(금)**, 19일간
> 삼성/KB국민/비씨/신한카드 결제 시

여기서 세 가지를 적어둡니다.

| 적을 값 | 위 예시에서 | 설명 |
|---|---|---|
| 사전행사 시작 | `2026-08-17` | 이 날부터 사전행사 행사가 자동 선택됩니다 |
| 본행사 시작 | `2026-09-05` | **사전행사 끝난 다음 날**. 이 날부터 본행사 행사로 바뀝니다 |
| 사전행사 조건 | `삼성/KB국민/비씨/신한카드 결제 시` | 사전행사 안내에 함께 표시됩니다 |

> 사전행사 시작 **전**에는 어떤 행사도 자동 선택되지 않습니다 (아직 행사 기간이 아니므로).
> 조건이 따로 없으면 `사전행사 조건:` 뒤를 비워두시면 됩니다.

## 4단계 — `시즌설정.txt` 고치기

**바로가기 2번**을 엽니다 → https://github.com/muttul58-coder/GS25_Order/edit/main/시즌설정.txt

편집 화면이 바로 열립니다.
(직접 찾아가려면: 저장소 첫 화면에서 `시즌설정.txt` 클릭 → **연필 아이콘**)

**쌍점(`:`) 뒤의 값만 고치시면 됩니다.**

```
매장 이름: LG 생산기술원점
매장 담당자: 양창호
매장 전화번호: 010-7568-3522

시즌 이름: 2027 설날
카탈로그 주소: https://gs25mobile.com/2027_1st/products.json
바코드 PDF: BarcodeSource/20270105.pdf

사전행사 시작: 2027-01-05
본행사 시작: 2027-01-20
사전행사 조건: 삼성/KB국민/비씨/신한카드 결제 시
```

바꿀 곳은 보통 **시즌 3줄과 행사기간 3줄** 뿐입니다. `바코드 PDF` 는 1단계에서 올린
파일 이름을 `BarcodeSource/` 뒤에 그대로 적습니다.

다 고치면 아래 **Commit changes** 를 누릅니다.

> `#` 으로 시작하는 줄은 설명이라 무시됩니다. 지우셔도 되고 두셔도 됩니다.
> 줄 순서는 상관없고, 빈 줄도 마음대로 넣으셔도 됩니다.

**이렇게 적어도 알아듣습니다** — 너무 조심하지 않으셔도 됩니다.

| 이렇게 적어도 | 이렇게 읽습니다 |
|---|---|
| `사전행사 시작: 2027.1.5` 또는 `2027/01/05` | `2027-01-05` |
| `시즌 이름: "2027 설날",` (따옴표·끝쉼표) | `2027 설날` |
| `담당자: 양창호` (짧은 이름) | `매장 담당자` |
| `카탈로그 링크:` / `바코드파일:` | `카탈로그 주소` / `바코드 PDF` |

반대로 **이름을 잘못 적으면 그냥 넘어가지 않고 멈춥니다.** 예를 들어
`사전행사시자: ...` 라고 오타를 내면 이렇게 알려줍니다.

```
  6번째 줄:  사전행사시자: 2027-01-05
      -> 모르는 이름입니다.  '사전행사시작' 을(를) 쓰시려던 것 같습니다.
```

틀린 곳이 여러 군데여도 **한 번에 모두** 알려주니, 한 줄씩 고쳐가며 여러 번
실행하실 필요가 없습니다.

매장 이름·담당자·전화번호가 바뀌었다면 위쪽 3줄도 같이 고치세요.
주문서 맨 위에 그대로 표시됩니다.

## 6단계 — 확인 (중요)

갱신 후 **반드시** 확인해 주세요.

1. 상품코드 몇 개를 넣어 **상품 이름과 가격**이 맞는지
2. **행사**가 카탈로그와 같은지
3. **인쇄해서 바코드를 실제 스캐너로 찍어보기**

> 바코드가 제일 중요합니다. 명절마다 **같은 상품코드가 다른 상품을 가리키기** 때문에
> (2026 추석에는 유지된 코드 371개의 내용물이 바뀌었습니다) 여기가 틀어지면
> 주문서에 찍힌 바코드가 엉뚱한 상품으로 스캔됩니다.

## 실행이 빨간 ✗ 로 끝났을 때

빨간 ✗ 를 누르고 **시즌 갱신 실행** 항목을 펼치면 `[!]` 로 시작하는 줄에 원인이 있습니다.

| 메시지 | 뜻과 조치 |
|---|---|
| `시즌설정.txt 을(를) 읽지 못했습니다` | 아래에 몇 번째 줄이 왜 잘못됐는지 그대로 적혀 있습니다 |
| `바코드 PDF가 없습니다` | `바코드 PDF` 줄의 이름과 실제 올린 파일 이름이 다릅니다 |
| `카탈로그를 읽지 못했습니다` | `카탈로그 주소`가 틀렸습니다. 브라우저에 붙여넣어 열리는지 확인 |
| `확인이 필요한 아이콘` | 아래 참고 |
| `두 소스가 완전히 일치하지 않습니다` | PDF와 카탈로그의 상품이 다릅니다. 같은 시즌 파일이 맞는지 확인 |

### "확인이 필요한 아이콘" 이 나오면

행사 표시(1+1, 2+1 …)는 카탈로그에 **숫자가 아니라 그림**으로만 들어 있습니다.
그래서 프로그램이 **아이콘 그림 자체를 기억해 두었다가** 새 시즌 그림과 맞춰봅니다.

- 그림이 지난 시즌과 **똑같으면** — 번호가 12번에서 37번으로 바뀌었어도
  알아서 같은 행사로 처리합니다. **하실 일이 없습니다.**
- 그림이 **처음 보는 것**이거나, **번호는 그대로인데 그림이 바뀌었으면** —
  이때만 멈추고 물어봅니다. **이것만 수동 작업입니다.**

물어보는 경우 이렇게 하시면 됩니다.

1. 실행 화면 아래 **Artifacts** 에서 `확인이-필요한-아이콘` 을 내려받습니다
   (그림 한 장에 번호와 함께 모아 놓았습니다)
2. 실행 기록에 적어준 줄을 `시즌설정.txt` **맨 아래에** 그대로 붙여넣고 값만 고칩니다

```
구매혜택 56: 3+1      ← 그림에 "3+1" 이라고 적혀 있으면
구매혜택 57: 없음      ← 무료배송·냉장·할인 등 덤이 아닌 그림이면 '없음'
```

3. 저장하고 5단계를 다시 실행합니다

한 번 적어두면 그 그림은 계속 기억되므로, **다음 시즌부터는 다시 묻지 않습니다.**

> 그림에 `9월 5일부터` 같은 날짜가 함께 적힌 것도 있습니다. 비율만 보고 적으면 됩니다
> (`3+1 9월 5일부터` → `3+1`). 날짜는 `사전행사 시작` / `본행사 시작` 에서 따로 관리합니다.

> **"번호는 그대로인데 그림이 바뀌었습니다"** 가 제일 조심할 경우입니다.
> 그냥 넘어가면 작년 비율로 올해 주문이 나가기 때문에, 일부러 멈추게 해두었습니다.
> 그림을 보고 확인한 뒤 위와 같이 한 줄 적어주세요.

## 자주 묻는 것

**Q. 잘못 눌렀는데 되돌릴 수 있나요?**
네. 모든 갱신이 커밋으로 남습니다. 개발자에게 "이전 상태로 되돌려달라"고 하면 됩니다.
불안하면 **확인만하기** 옵션으로 먼저 돌려보세요.

**Q. 매장 전화번호만 바꾸고 싶어요.**
`시즌설정.txt` 의 `매장 전화번호` 줄만 고치고, **바코드도 다시만들기 체크를 해제**하고 실행하세요. 몇 초면 끝납니다.

**Q. `season.json` 은 뭔가요? 고쳐야 하나요?**
아니요. 구매혜택 아이콘 그림을 기억해두는 파일이라 **프로그램이 알아서 씁니다.**
갱신할 때마다 자동으로 바뀌므로, 열어보거나 고치지 마세요.

**Q. 행사가 카탈로그와 다르게 나옵니다.**
주문서의 행사 칸은 언제든 직접 바꿀 수 있습니다. 매장 사정으로 다른 경우가 있어
자동 선택은 어디까지나 처음 채워주는 값입니다.

**Q. 상품이 몇 개인지 어떻게 아나요?**
실행 기록의 `시즌 갱신 실행` 항목에 상품 수, 행사 수가 모두 찍힙니다.
카탈로그 사이트의 "사전 구매 행사 총 ○○품목" 과 비교해 보면 맞게 읽었는지 확인됩니다.
